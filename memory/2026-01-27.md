### Core Workflows

#### 1. Capture (`"capture this"`)
- **Trigger detection** - Determines if input is task, note, or scan request automatically
- **Date parsing** - Converts natural language ("tomorrow", "next Friday") to ISO format
- **Project detection** - Auto-associates with relevant projects via context clues
- **Wiki-link auto-detection** - Links to related existing notes (0.85 threshold, max 5 links)
- **Direct placement** - Tasks go straight to correct location, NO INBOX STOP

**Key principle:** Vague actions are REJECTED. Must have concrete verb + object + context.

**Examples rejected:**
- "Think about X" ❌
- "Look into Y" ❌
- "Work on Z" ❌

**Examples accepted:**
- "Call John at 555-1234" ✅
- "Draft email to Sarah about timeline" ✅
- "Search Google for venue options, list top 3" ✅

#### 2. Process Inbox (`"process inbox"`)
- **GTD clarify questions:**
  1. What is it?
  2. Is it actionable?
  3. What's the desired outcome? (single task vs project)
  4. What's the next physical action? (must be concrete)
  5. Where does it belong?

- **Inbox threshold gate:** Planning BLOCKED if ≥5 unprocessed items (enforces GTD discipline)
- **Auto-project creation:** When multi-step outcome detected, creates project folder + summary file + first task
- **Project template includes:** Desired Outcome, Next Actions, Waiting On sections + Dataview queries

#### 3. Daily Planning (`"plan my day"`)
- **Pre-check:** Inbox must have <5 items before planning allowed
- **Four criteria collection:**
  - Energy (high/medium/low)
  - Contexts (@computer, @phone, @home, @office, @errands)
  - Time available (full day / half day / limited / constrained)
  - Hard deadlines (must happen today)

- **Scoring algorithm:** Additive scoring with weighted factors
  - Due today: +5
  - Due within 3 days: +3
  - Priority high: +3
  - Context match: +2
  - In progress bonus: +2
  - Hard deadline override: +10
  - Context mismatch: -3
  - Energy mismatch: -2

- **Selection:**
  - Must-Do (Top 3) - Commitments for the day
  - Should-Do (Next 5) - Important but flexible
  - Quick Wins - Tasks ≤15 minutes

- **Source tags:** Each task gets `#source/{folder-type}/{kebab-filename}` for closeout sync-back

#### 4. Daily Closeout (`"close out day"`)
- **Review:** Walk through each planned task (complete/partial/deferred/dropped)
- **Capture unplanned work:** Anything done off-plan
- **Sync to source:** Updates source project files via source tag parsing
  - Completed → Move to "Completed" section with date
  - Partial → Add progress note inline
  - Deferred → No change (carries to tomorrow)
  - Dropped → Move to "Someday/Maybe"

- **Tomorrow's draft:** Auto-generates next day's plan with carry-over tasks

### Source Tag System

**Format:** `#source/{folder-type}/{kebab-filename}`

**Example:** Task from `Projects/Website-Redesign.md` gets tag `#source/projects/website-redesign`

**Closeout parses tag to:**
1. Locate source file: `Projects/Website-Redesign.md`
2. Find task in "Next Actions" section
3. Update status based on review
4. Write updated file

**Conversion rules:**
- `projects` → `Projects/`
- `website-redesign` → `Website-Redesign.md` (kebab to Title Case)

### Decision-Making Framework

**Use my best instinct when:**
- Context is clear from the system structure
- Similar decisions have been made before
- The action follows established conventions
- It's a routine operation (capture, link, organize)

**Ask for clarification when:**
- Storage location is genuinely ambiguous (Project vs Area vs Resource?)
- Project creation threshold unclear (Is this multi-step or single task?)
- Priority/importance unclear
- Multiple valid interpretations exist
- Action could have significant consequences

**Low confidence → Ask first:**
- "Is this a Project (active, has deadline) or an Area (ongoing responsibility)?"
- "Should this go in Career or Personal area?"

**GitHub Repository Review (2026-01-27 14:01 UTC):**
Source: https://github.com/callumalpass/tasknotes

**Critical Architectural Understanding:**

TaskNotes is built on **Obsidian Bases** (core plugin):
- Tasks = Markdown files with YAML frontmatter
- Views = `.base` files in `TaskNotes/Views/` directory
- No plugin-specific database - 100% portable markdown
- Bases reads properties from frontmatter and creates database-like views
- All filtering, sorting, grouping happens in `.base` files

**Formula Properties in .base Files:**
```yaml
formulas:
  daysUntilDue: if(due, ((number(date(due)) - number(today())) / 86400000).floor(), null)
  isOverdue: due && date(due) < today() && status != "done"
  urgencyScore: formula.priorityWeight + max(0, 10 - formula.daysUntilNext)
  efficiencyRatio: (timeTracked / timeEstimate * 100).round()
```

These computed fields enable:
- Smart sorting by urgency score
- Filtering overdue tasks
- Efficiency tracking (time tracked vs estimated)
- Days until due calculations

**Key Capabilities:**
- ✅ All property names configurable (can remap `deadline` → `due`)
- ✅ Custom fields immediately queryable in Bases
- ✅ `.base` files are plain text (can edit directly or duplicate for custom views)
- ✅ HTTP API optional (http://127.0.0.1:8090/api)
- ✅ CLI tool available: https://github.com/callumalpass/tasknotes-cli
- ✅ Browser extension: https://github.com/callumalpass/tasknotes-browser-extension
- ✅ Webhooks for external service notifications
- ✅ Time tracking with start/stop per task
- ✅ Pomodoro timer built-in
- ✅ Calendar sync (Google, Microsoft OAuth, ICS feeds)

**Language Support:**
- UI: English, German, Spanish, French, Japanese, Russian, Chinese
- NLP: English, German, Spanish, French, Italian, Japanese, Dutch, Portuguese, Russian, Swedish, Ukrainian, Chinese

**Important for Our Implementation:**
- Bases plugin MUST be enabled for views to work
- Direct file operations (what we're doing) work independently of Bases
- Dataview queries in project pages work with TaskNotes task files
- Formula properties only work in TaskNotes .base views (not Dataview)
